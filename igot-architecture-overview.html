iGOT Karmayogi platform architecture

Four portals and a mobile app reach, through two gateway front doors, a Karmayogi-specific service layer that extends — never forks — the open-source Sunbird building blocks (Knowlg and Lern). Everything persists in a set of purpose-built stores, talks asynchronously over Kafka, and is mined nightly into a BI warehouse — all running on Kubernetes in Google Cloud.

Scope: whole platform, incl. Sunbird Knowlg + Lern No APIs · no use cases · no data models ✓ Components traced in the feature HLDs · Oct 2026 ◌ = documented from contracts / config only

The platform in four layers

Read left to right the way a request travels: people → gateways → services → data. iGOT services and the two upstream Sunbird building blocks — Knowlg and Lern — sit shoulder to shoulder in the services layer: Kong routes to any of them directly, and iGOT calls into the Sunbird blocks sideways. Four flows that cross the layers

Shown at ring level only — the per-feature HLD pages carry the service-by-service version.

Learn a Karmayogi takes a course

  1. PortalsGateway portal or mobile enters via /apis → Kong
  2. Knowlg search-service to discover; Lern course-service to enrol and track progress
  3. Data state in Cassandra; completion event on Kafka
  4. iGOTLern karma points, certificates react to the event
  5. iGOTData next nightly run refreshes leaderboards and the warehouse

Create & publish content reaches learners

  1. PortalsGateway creation portal → gateway
  2. Knowlg knowledge-platform: Draft → Review → Live
  3. Data publish event on Kafka
  4. Knowlg Flink publish & indexer jobs
  5. Data Elasticsearch / Neo4j / GCS updated; visible to learners

Onboard a user or a department joins

  1. Portals public sign-up, admin portal or CSV upload
  2. Gateway Keycloak identity
  3. iGOT sunbird-cb-ext orchestrates; workflow approvals where required
  4. Lern sunbird-lms-service creates the account
  5. iGOTData notification mail; user directory in Cassandra / Elasticsearch

Measure the platform reports on itself

  1. iGOTData cb-core-data extracts nightly from the live stores
  2. iGOT pre-join, then ~46 independent Stage-2 jobs
  3. Data Postgres warehouse + BigQuery → Looker (external)
  4. Data Redis live-dashboard keys; Cassandra karma & leaderboards
  5. Portals read back by portals and admins
