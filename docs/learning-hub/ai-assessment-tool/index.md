# AI Assessment Tool

An AI-powered pipeline that turns a course's own PDF/video content — or
purely a set of Karmayogi Competency Model (KCM) competencies, with no
course at all — into a ready-to-publish, multi-question-type, multilingual
assessment, generated by Google Gemini via Vertex AI.

- **Repos**:
    - `ai-assessment-service` (traced at `origin/cbrelease-4.8.37`, commit
      `82fef3e`) — the whole generation engine: a FastAPI API, an
      `aiokafka` worker, and a Streamlit reference UI, all in one repo.
    - `sunbird-cb-uiproxy` (traced at `origin/cbrelease-4.8.41`, commit
      `423875a`) — the Karmayogi gateway's proxy routes
      (`/proxies/v8/ai/assessments/*`) that forward to this service via
      Kong, plus the `/proxies/v8/workflow/aiAssessment/*` routes for the
      approval flow below.
    - `sunbird-cb-workflow` (traced at `origin/cbrelease-4.8.39.2`, commit
      `8ae07a0`) — the approval workflow that grants a user the
      `AI_ASSESSMENT_CREATOR` role, gating who may call the generator at
      all.
    - `sunbird-devops` (traced at `origin/cbrelease-4.8.41`, commit
      `978c17a12`) — Kong route definitions, Helm charts, and env
      templating for the API, worker, and Streamlit UI as three separate
      Kubernetes deployments.
- **Self-description in code**: the health route returns
  `{"status": "healthy", "service": "assessment-generator"}`
  (`ai-assessment-service:src/assessment/api.py:74`); the repo's own README
  calls it "Course Assessment Generation"; `architecture.md` calls it the
  "AI-powered Assessment Generation system". No single canonical product
  name is used consistently across the repo's own docs.
- **Shape**: one standalone, async, event-driven microservice
  (`ai-assessment-service`) that the rest of the platform reaches only
  through a gateway proxy and gates only through a separately-run approval
  workflow — the three repos never call each other directly; they're
  stitched together by a JWT role claim and a Kong route.
- **Status**: ✅ the generation engine itself is traced end-to-end,
  file-and-line, including its Gemini/Vertex prompting strategy, KCM
  context-caching, Kafka event flow, and every export format. ⚠️ two repos
  that were candidates for this trace — `cbp-ai-ui` and
  `sunbird-cb-creationportal` — were checked and found to have **no
  code-level connection** to this feature at their traced commits (see the
  [As-Built Requirements](as-built-requirements.md) "Out of scope" note);
  they are excluded here rather than force-fit. The actual **UI that lets a
  course author trigger generation from within Karmayogi** was not found in
  any of the four repos traced — see the honest gap in [HLD](hld.md).

## In one paragraph

A user holding the `AI_ASSESSMENT_CREATOR` role — granted only after an SPV
Publisher approves their request in `sunbird-cb-workflow`
(`AiAssessmentServiceImpl.java`) — calls
`POST /proxies/v8/ai/assessments/v1/generate` through the Karmayogi gateway.
`sunbird-cb-uiproxy` forwards the multipart request to `ai-assessment-service`
via Kong. The API validates the caller's JWT (RS256, JWKS fetched from the
Sunbird SSO realm) and the `AI_ASSESSMENT_CREATOR` role claim, then checks a
Postgres-backed cache: an identical prior request from the same user returns
instantly; an identical request from *any* user is cloned to the caller
instantly; otherwise a new job row is created (`PENDING`) and a request event
is published to Kafka. A separate worker process consumes that event, fetches
the course's PDFs and video subtitles from the Karmayogi content and
transcoder APIs (with a three-tier local-disk/GCS/API cache), builds one
large prompt combining the source content, a cached KCM competency reference
dataset, and per-question-type/per-Bloom's-level instructions, and calls
Gemini with a strict JSON response schema. The result — a `blueprint` plus up
to five question-type buckets — is saved back to the same Postgres row
(`COMPLETED`), and a lifecycle event is published to Kafka. The caller polls
for status, can edit the saved JSON, and can download the result as JSON,
one of two CSV schemas, a font-embedded PDF, or a DOCX.

## How an AI Assessment Creator experiences it

1. **Gets the role**: someone with the SPV Publisher role approves their
   `ai_assessment` workflow request; on approval, a Kafka-consumed step
   grants them `AI_ASSESSMENT_CREATOR`
   (`sunbird-cb-workflow:WorkflowApplicationConsumer.java:50-75`).
2. **Requests generation**: submits course IDs (or uploaded PDF/VTT files
   for a Standalone assessment, or just KCM competency selections for a
   Competency assessment), an assessment type, difficulty, question-type
   counts, optional Bloom's-taxonomy distribution, and a target language.
3. **Gets an instant result, or waits**: if an identical request already has
   a completed result — theirs or another user's — it's returned
   immediately (cloned into their own row if it was someone else's). Only a
   genuinely new request queues a background job.
4. **Polls for completion**: `GET .../status/{job_id}` until `status` is
   `COMPLETED` or `FAILED`.
5. **Edits the result**, if needed — the generated JSON's `assessment_data`
   can be overwritten in place via `PUT .../update/{job_id}`, as long as
   they're the row's owner.
6. **Downloads** the finished assessment as JSON, CSV (two schema flavors),
   PDF, or DOCX.
7. **Reviews history**: `GET .../history` lists every job the user owns or
   has cloned.

## Actors

| Actor | Role |
|---|---|
| AI Assessment Creator | The end user generating assessments — must hold `AI_ASSESSMENT_CREATOR`; interacts entirely through the gateway-proxied REST API (or the bundled Streamlit reference UI) |
| SPV Publisher | Approves or rejects a user's request for the `AI_ASSESSMENT_CREATOR` role, in `sunbird-cb-workflow` |
| Karmayogi content/transcoder platform | Source of course PDFs, video VTT captions, and metadata that the worker fetches for course-based generation |
| Google Vertex AI (Gemini) | Generates the assessment JSON against a strict schema, using a context-cached KCM reference dataset |
| Platform operator | Deploys and configures the three Kubernetes workloads (API, worker, Streamlit UI) and their Kong routes, per `sunbird-devops` |

## The one decision that defines the feature

> This is a single self-contained microservice, not a platform feature woven
> into the authoring tools. `ai-assessment-service` never calls
> `sunbird-cb-workflow`, and `sunbird-cb-workflow` never calls
> `ai-assessment-service` — the two are connected only by a role claim
> (`AI_ASSESSMENT_CREATOR`) baked into the caller's JWT at login time, issued
> by a Keycloak/Sunbird-SSO realm neither repo owns. There is no traced UI
> anywhere in `sunbird-cb-creationportal` (the platform's own authoring app)
> that calls this service — course authors would need a frontend outside the
> four repos scoped here, or the bundled Streamlit app, to actually use it.
> The service also caches and clones aggressively: an identical request
> (same course IDs + same generation parameters, hashed) from a *different*
> user returns another user's already-generated content, not a fresh Gemini
> call — a deliberate cost-saving design, not a bug, but one worth knowing
> before assuming every "instant" result was freshly generated for that
> user.
