Blended Program
Instructor-led learning that mixes online modules with classroom sessions — batches, seat limits, attendance and offline session tracking.
Category  Blended Program Route  /app/toc/:programId Workflow  blendedprogram ✓ Verified from repos · Aug 2026

What it is

A Blended Program pairs self-paced online content with scheduled instructor-led sessions. An MDO creates a program, opens batches with seat limits, and Karmayogis apply or are nominated. Completion requires both the online modules and attendance at the offline sessions.

Batches & seats

Enrolment windows, capacity caps and waitlists per batch.

Attendance

Offline session check-in that counts toward completion.

Approvals

Nomination and MDO-admin approval before a seat is confirmed.

How a Karmayogi experiences it

1 · DISCOVER

Finds the program in the Learning Hub

2 · APPLY

Requests a seat in an open batch

3 · LEARN

Online modules plus classroom sessions

4 · CERTIFY

Certificate on full completion

Actors

Karmayogi (the learner), MDO Admin (the learner's ministry/department administrator, an approver), Program Coordinator (PC) (owns the program, an approver, works the Creation Portal console), Author (creates the program content), Batch Creator (opens and maintains batches), and Instructor (assigned per batch, runs sessions and marks attendance). Which approvers are involved depends on the batch's approval type — see the four modes in LLD.

Learner journeys

Karmayogi
UC-1 · Request enrolment into a batch

From the program's TOC page the learner picks an open batch and requests a seat. Before the request goes out, the portal checks for a conflict (an active enrolment in another Blended Program blocks the request) and, if the batch demands it, collects a profile survey / questionnaire first (driven by batchAttributes.userProfileFileds or the program's wfSurveyLink). The request creates a workflow application in state INITIATE, then moves to the first approval step.

POST workflow/blendedprogram/enrol
Karmayogi
UC-2 · Withdraw an enrolment request

Until approved (and, depending on program rules, after), the learner can withdraw. The workflow moves to WITHDRAWN; the seat is released. The UI shows the request state on the batch card throughout (“sent for MDO approval”, “approved”, …) via the status-message mapping.

POST workflow/blendedprogram/unenrol (action WITHDRAW)
Karmayogi
UC-3 · Learn: online modules + sessions

Once APPROVED, the learner is enrolled in the batch and the program appears in My Learning. Online content progress is written per node; classroom/offline sessions come from batchAttributes.sessionDetails_v2, and session completion contributes to the overall completion percentage.

POST content/v2/state/read · GET learner/course/v4/user/enrollment/details/:userId
Karmayogi
UC-4 · Submit a program assignment

Blended programs can carry assignments: the learner uploads an answer file, submits a draft, then submits final; the coordinator side is notified and can evaluate. Files live in the BP assignment store.

POST assignment/v1/submitDraft · assignment/v1/submit · storage/v1/bp/assignment/answer · v1/notifyAssignment/submit

Approver & admin journeys

MDO Admin / PC
UC-5 · Approve or reject a request

Approvers see pending applications in their console and act on each. A one-step batch needs only MDO or PC; a two-step batch chains both in the configured order. Approval moves the workflow to the next state (SEND_FOR_PC_APPROVAL or APPROVED); rejection ends it at REJECTED.

POST workflowhandler/transition · workflow/v2/userWFApplicationFieldsSearch · workflowhandler/applicationsSearch
MDO Admin / PC
UC-6 · Remove an enrolled learner

After approval, an admin can remove a learner from the batch; the workflow records REMOVED and the seat frees up. The learner sees the removal message on the program page.

POST workflowhandler/transition
Batch Creator
UC-7 · Create and configure a batch

From the Creation Portal, a batch is opened as enrollmentType: "invite-only" with name, start/end/enrolment-end dates, seat cap, venue address and lat-long, QR attendance on/off, instructors, cadre list and profile-field requirements. If custom profile fields are chosen, the portal auto-creates a survey form and stamps its link into the batch; a default certificate template is auto-attached on creation.

POST learner/course/v1/batch/create · forms/v2/createForm · course/batch/cert/v1/template/add
MDO Admin / PC
UC-8 · Generate the batch enrolment report

Requester role is validated (MDO/PC roles only), then the report is generated asynchronously: a request row goes to IN_PROGRESS, a Kafka consumer joins workflow state with enrolment data, and the finished file is downloaded per org/course/batch.

POST bp/v2/generate/report · bp/v2/bpreport/status · GET bp/v1/bpreport/download/:orgId/:courseId/:batchId/:file

Authoring & batch management (Creation Portal)

Author / Content Creator
UC-9 · Create and publish the program itself

A Blended Program is authored in sunbird-cb-creationportal like any collection: create → build hierarchy → send to review → publish (with reject and retire paths). Assessments attach as question sets with their own review/publish cycle.

POST action/content/create · content/hierarchy/update · content/v3/review/:id · content/v3/publish/:id
Program Coordinator / Admin
UC-10 · Nominate & bulk-enrol learners

Beyond self-enrolment, admins can nominate learners into a batch (select or bulk-upload — the workflow is created on the learner's behalf) or bulk-enrol directly. Users can also be added to or removed from a batch individually.

POST workflow/blendedprogram/nominate · program/v2/admin/bulkEnroll · authApi/batch/addUser / removeUser
Program Coordinator / MDO
UC-11 · Work the request queue in the Creation Portal

The program's detail page has a “New requests” console: approve (with the next-step message when a second approval is pending) or reject with a mandatory reason. The pending queue can be exported as CSV for offline processing.

POST v1/blendedprogram/workflow/update · GET workflow/blendedprogram/getUserApprovalDataInCsv
Instructor / Coordinator
UC-12 · Run sessions and mark attendance

Sessions (offline or online) live in the batch's session plan. Attendance is taken either by QR code (per batch, downloadable, with scan status) or manually in the attendance dialog — and marking attendance is literally a progress write: attended = status 2 / 100% on the session node, which is why sessions count toward completion. Marking is time-boxed after the session date.

POST blendedprogram/v1/update/progress · GET batch/v1/enrollment/qrcode/download / status
Coordinator
UC-13 · Track learners and certify

Per-batch learner progress is read in bulk (v2 endpoint), certificates ride the batch template attached at creation, and can be re-issued for corrections.

POST authApi/batch/getUserProgressV2 · course/batch/cert/v1/issue?reIssue=true
Batch Creator
UC-14 · Maintain the batch over its life

Batch details and attributes are editable after creation (same payload shape via update); an unused batch can be deleted. Mandatory-profile-field options, cadre lists and the default certificate template all come from system settings, so they are configuration rather than code.

PATCH authApi/batch/update · POST learner/course/v1/batch/delete · data/v2/system/settings/get/…

Edge cases worth documenting

SituationBehaviour
Learner already in another Blended ProgramEnrolment request is blocked client-side with a conflict message before any workflow is created.
Batch fullEnrolled/approved count is checked via the status-count API against currentBatchSize; the request CTA is disabled.
Enrolment window closedenrollmentEndDate on the batch gates the request button.
Survey required but not submittedThe enrol call is not made until the form (via forms/v2/getFormById / saveFormSubmit) is completed.
Duplicate requestThe user's existing workflow application is fetched on page load (blendedprogram/user/search); the UI renders the current state instead of offering enrol again.
Attendance marked lateThe attendance dialog is disabled once the allowed window after the session date has passed (date check in content-sessions).
Rejection without a reasonNot possible from the Creation Portal console — the reject dialog requires a reason, which travels with the workflow update.

Course
The standard self-paced unit of learning — one-click enrolment, node-by-node progress, Karma Points and a certificate on completion.
Category  CourseRoute  /app/toc/:courseId✓ Verified from repos · Aug 2026

What it is

The building block of the Learning Hub. Unlike a Blended Program, a Course has no approval workflow: tapping Enrol writes the enrolment directly and the course lands in My Learning at 0%. Progress is tracked per content node, Karma Points accrue on completion events, and a certificate issues when every mandatory node is complete.

Instant enrolment

One call, no approvers — the contrast that defines every other category.

Node-level progress

Every video, PDF and quiz reports its own state; the course rolls them up.

Rewards

Karma Points and certificates hang off the same completion signal.

Karmayogi
UC-1 · Enrol

From the TOC page, one click enrols into the course's batch. Re-clicking is safe; the record is keyed on user + course + batch.

POST learner/course/v1/enrol
Karmayogi
UC-2 · Learn & resume

The viewer writes real-time progress; lastReadContentId powers the Resume button back into the exact node.

POST content/v2/state/read · user/realTimeProgress/update
Karmayogi
UC-3 · Leave a course

Unenroll is soft — the course leaves My Learning but history and any earned certificate stay.

POST course/v2/unenroll
Karmayogi
UC-4 · Complete, claim, certify

At 100% the learner claims Karma Points and downloads the certificate; ratings and share-with-a-colleague close the loop.

POST claimkarmapoints · GET cohorts/course/batch/cert/download/:id · POST user/rating · user/v1/content/recommend

Curated Program
An editorially assembled collection of courses enrolled as one unit — auto-assigned batch, progress rolled up from the child courses.
Category  Curated ProgramEnrol  curatedprogram/v1/enrol✓ Verified from repos · Aug 2026

What it is

A parent collection whose children are ordinary courses. Enrolling in the program auto-assigns the learner into its batch in one call — no approval, no batch picking — and the program's completion is computed from the child courses' individual enrolments. The sibling category Moderated Program uses the same mechanics through a separate open-program enrol endpoint.

One-click, auto-batched

The enrol call resolves the batch itself.

Roll-up progress

Parent % is derived by merging each child course's enrolment.

Editorial surface

Featured on home strips and campaign pages via curated collections.

Karmayogi
UC-1 · Enrol in the program

One call; the response carries the assigned batch. Moderated Programs route to the open-program variant of the same call.

POST curatedprogram/v1/enrol · openprogram/v1/enrol
Karmayogi
UC-2 · Work through child courses

Each child behaves as a normal course; the parent card shows the merged percentage and the next course to take.

GET enrollment/details · POST course/v1/hierarchy/:id
Karmayogi
UC-3 · Complete and certify

When the roll-up reaches 100%, program-level completion triggers the certificate exactly as for a course.

GET cohorts/course/batch/cert/download/:id
Author / Curator
UC-4 · Assemble and publish

Built in the Creation Portal as a collection of existing courses, through the same create → review → publish cycle.

POST action/content/create · content/hierarchy/update · content/v3/publish/:id

My Assigned Courses
Courses pushed to a learner by their organisation — resolved by an access-settings rules engine, including external partner (CIOS) courses.
Service  cb-ext-course-serviceAPI  user/v2/assignedcourses✓ Backend verified from source

What it is

The learner-facing view of content assignment: courses an MDO has directed at a user, surfaced as “My Assigned Courses” with mandatory-course nudges. This is the one Learning Hub feature whose backend is fully in the attached repos — CourseAccessController and CourseAccessServiceImpl in cb-ext-course-service.

Rules, not lists

Assignments resolve from cached access-setting rules, then a composite search finds matching courses.

External courses too

A dedicated endpoint resolves assigned partner content via the CIOS integration search.

Admin view

An admin can read any user's assignments through the admin variant.

Karmayogi
UC-1 · See what's assigned to me

The portal calls the v2 endpoint with the user's token; the service resolves the org's access-setting rules and returns the matching courses with the learner's enrolment state.

POST user/v2/assignedcourses
Karmayogi
UC-2 · Assigned external (partner) courses

Marketplace/CIOS content assigned by the org is resolved by a separate endpoint against the CIOS search host.

POST user/v1/assigned/externalcourses
MDO Admin
UC-3 · Inspect a learner's assignments

Support and compliance view: the admin endpoint takes the target userId in the path and answers with that user's assigned set.

POST admin/user/v2/assignedcourses/:userId
Karmayogi
UC-4 · Mandatory-course pressure

Assigned mandatory courses drive the notification modal and the mandatory-course shelf, with deadlines shown until completion.

Feature route /app/learn/mandatory-course · GET content/user/info

Standalone Assessment
An assessment taken as its own learning object — question sets served securely, auto-saved attempts, versioned submission and result APIs, retakes.
Category  Standalone AssessmentLibrary  sb-cb-ui-assessment✓ Verified from repos · Aug 2026

What it is

A question set consumed through the assessment player rather than the content viewer. Questions are fetched separately from the assessment shell (so answers are never shipped with the paper), attempts auto-save, and submission and results run through versioned endpoints currently at v5. The same machinery also powers assessments embedded inside courses and the pre-enrolment assessments some programs require.

Split delivery

Assessment shell and question bodies come from separate reads.

Attempt safety

Auto-save during the attempt; submission is explicit.

Retakes

A dedicated retake endpoint governs re-attempts per assessment.

Karmayogi
UC-1 · Start an attempt

The player reads the assessment shell (sections, timing, rules), then fetches questions by id in batches as the learner progresses.

POST assessment/v5/read · question/v5/read
Karmayogi
UC-2 · Auto-save & submit

Answers are saved server-side during the attempt, then submitted; the submit API has evolved v2→v5 and old versions remain for embedded/legacy content.

POST assessment/save · user/evaluate/assessment/submit/v5
Karmayogi
UC-3 · See results & retake

Result read is versioned alongside submit; retakes are requested per assessment id and honour the configured attempt policy.

POST user/assessment/v5/result · GET user/assessment/v5/retake/:assessmentId
Author
UC-4 · Author the question set

Created in the Creation Portal as a question set with its own review/publish cycle; CQF quality checks have their own create/update/autopublish path.

POST questionset/v1/create · review · publish · cqfquestionset/…

Comprehensive Assessment Program
A program-level assessment category, typically assigned/mandated, that reuses the assessment engine end to end.
Category  Comprehensive Assessment ProgramStatus  thin in attached repos

What the code shows

CAP appears in the attached repos as a distinct ECourseCategory with three verified behaviours: it is the default deep-link target of the mandatory-notification modal (learners are pushed to it by notification), its cards are exempt from end-date display in the consumption strips, and it has its own section handling in the home-page content strips. Its consumption mechanics are those of the assessment engine documented under Standalone Assessment.

Honest gap: no CAP-specific enrolment or evaluation endpoint appears in the attached repos — the category rides the shared assessment and course rails. If there is a dedicated CAP backend (e.g. in the assessment service), attaching that repo would let this page say more. Treat this page as a stub-plus, not finished documentation.

Explore Content
The platform-wide discovery surface — global search, the Explore menu, facet browsing and every “see all” listing, served by the composite search APIs.
Routes  /app/explore · /app/globalsearchService  search-service✓ Verified incl. gateway path

What it is

Explore Content is how a Karmayogi finds what to learn next. One search box at the top of the portal covers everything — courses, programs, assessments and events — and the Explore menu offers the same catalogue as browsable categories. Filters narrow the results to what fits: competency, topic, content provider, language, duration. There is nothing to set up and no path to follow; type a word or tap a tile, and the catalogue answers.

One search, everything

Courses, programs, assessments and events in a single result list — no need to know where content lives.

Filter to fit

Narrow by competency, provider, language or category until what remains is worth your time.

Always current

Newly published content shows up in search shortly after it goes live — no waiting for a catalogue refresh.

How a Karmayogi experiences it

1 · SEARCH

Type in the top bar, or open the Explore menu

2 · FILTER

Narrow by competency, provider or language

3 · PREVIEW

Open a result to see its details and ratings

4 · START

Enrol or begin learning right from the result

Karmayogi
UC-1 · Search from anywhere

The top bar and global search page send the query plus filters; facets in the response render the filter rail.

POST composite/v5/search (legacy strips: sunbirdigot/search)
Karmayogi
UC-2 · Browse by facet

Explore-menu tiles and filter chips are the same API with filters set and an empty query.

POST composite/v5/search with filters + facets
Program Coordinator
UC-3 · Role-aware search

v5 parses the JWT for roles and org; the PC console uses the dedicated Blended Program search.

POST composite/v4/bp/search
Author
UC-4 · Search while authoring

The Creation Portal searches drafts and published content through v4 search.

POST sunbirdigot/v4/search → composite/v4/search
