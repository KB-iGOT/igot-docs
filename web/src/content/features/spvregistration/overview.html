What it is

An SPV admin opens the Directory, chooses Create new, and enters a name, a category (state, ministry or, for volunteer organisations, autonomous), a description and a logo. The organisation is created and recorded in the platform's hierarchy. Because it starts with no users, the admin then creates its first administrator from the Create user screen; from there the organisation's own admin takes over. The same directory publishes registration links and QR codes, switches volunteer organisations on and off, and the Requests screens let the admin approve or reject what others have asked for — a new organisation, a new designation, or an email domain to be trusted.

Honest gap: several legacy screens call routes that nothing serves.
A new organisation has no admin

The Add-admin picker only searches existing users of the organisation, so the first administrator has to be created, not picked.

Approving a request creates nothing

Approving an organisation or designation request only changes its status; approving an email domain is the one that has an effect — it lets that domain skip manual approval.

How an SPV admin experiences it

1 · BROWSE

Directory tabs: organisations, CBP providers, volunteer, hierarchies

2 · CREATE

State, ministry or autonomous volunteer organisation

3 · FIRST ADMIN

Create user with an admin or leader role; activation email sent

4 · LINK

Publish a registration link and QR once designations are imported

5 · REVIEW

Approve or reject organisation, designation and domain requests
