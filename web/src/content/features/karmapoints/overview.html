What it is

A Karmayogi earns points for logging in, enrolling, completing, rating and attending events, and can convert unconverted points into Karma Coins (up to 300 a month). No request-path service computes a point: course-service, LMS-service and cb-ext only publish events to one Kafka topic, and a keyed Flink job awards, dedups, caps and reverses them, writing a Cassandra ledger and running total that cb-ext reads back.

Honest gap: the clients, not the processor, are the source of several displayed values — mobile and orgportal show 15 points for an ACBP course while the processor awards 5 + 5, and the mobile claim button hard-codes +10 against a processor claim of 5. See the As-Built tab.
One writer, many producers

Every ledger and wallet write happens in the Flink job; producers share one envelope but put the userId in a different place per event type.

Wallet is a Kafka round-trip

cb-ext validates and locks, returns 202; the job applies a frozen conversion plan with a Cassandra LWT claim and Redis dedup.

Two processors still deploy

V1 (seven topics) and V2 (one unified topic) both ship; which producers still feed V1 is not determinable from the code.
