Actors

Karmayogi (the learner), MDO Admin (an approver for their organisation), Program Coordinator (PC) (owns the program’s batches, approves, marks attendance, nominates), Lead trainer / co-trainer (bp_program_trainer, coordinator-level, scoped to chosen batches), Instructor (program_instructor, named on a batch), Author / reviewer / publisher.

Learner journeys

Karmayogi
UC-1 · Find a program and pick a batch

Batches whose enrolment end date has passed are not offered (and on web a batch with no end date is never enrollable). Seat state comes from a per-batch status count: enrolled = approved requests, applied = everything except withdrawn. The page warns at 80% full and when every batch is full.

POST learner/course/v1/batch/list · workflow/blendedprogram/enrol/status/count
Karmayogi
UC-2 · Clear the entry steps

Mandatory pre-requisite resources first; then (web) a client-side clash check; then a profile form if the batch sets userProfileFileds (with a cadre eligibility check when cadreList is set); then the program survey (wfSurveyLink). Answers are saved before the final confirmation, so cancelling leaves them submitted.

GET forms/v2/getFormById · POST forms/v2/saveFormSubmit
Karmayogi
UC-3 · Request a seat

The server re-checks volunteer eligibility, seat room (with a 20% request-time buffer) and schedule clash, writes a request at ENROLL_IS_IN_PROGRESS and returns; a Kafka consumer then moves it into the first approval state.

POST workflow/blendedprogram/enrol
Karmayogi
UC-4 · Withdraw a pending request

No reason is captured. Web disables it once the first approver of a two-step route has acted; neither web nor mobile offers it after approval. A withdrawal never un-enrols; only a removal does.

POST workflow/blendedprogram/unenrol (action WITHDRAW)
Karmayogi (mobile)
UC-5 · Self-enrol by scanning a QR

For programs with selfEnrollment = Yes. The app checks the QR matches the program and a batch, the enrolment end date, the seat state and — if the batch has a latlong — a 1000 m radius. The server approves on the spot, with no approver.

POST workflow/blendedprogram/qr/enrolments
Karmayogi
UC-6 · Learn: self-paced content and sessions

Start needs an APPROVED request and a batch in progress; a countdown shows until then. Sessions come from the batch’s sessionDetails_v2; web shows attendance (status 2 = marked) but cannot mark it.

POST learner/course/v4/user/enrollment/details · read/content-progres/:courseId
Karmayogi (mobile)
UC-7 · Mark attendance by QR

Session must be live (start to start + whole hours + 1 h), the phone within 1000 m of the batch latlong, and the QR must match the tapped session and batch. It is a plain progress write on the session node; a batch without latlong cannot mark attendance on mobile.

PATCH course/v5/content/state/update (status 2, 100%)
Karmayogi
UC-8 · Submit an assignment

PDF only; web checks the integer MB > 5, mobile 5 MB, the store 5000 KB. Draft then submit; the web preview’s “Discard” actually saves a draft. No due date exists in the learner code.

POST assignment/v1/search · storage/v1/bp/assignment/answer/… · PUT assignment/v1/submitDraft · POST assignment/v1/submit

Approver & coordinator journeys

Program Coordinator
UC-9 · Work the request queue

The batch page’s New requests tab lists SEND_FOR_PC_APPROVAL items oldest first. Approve asks for confirmation; Reject requires a reason (≤ 500 chars). The console acts on the PC step only.

POST workflow/blendedprogram/searchV2/pc · update/pc
Program Coordinator
UC-10 · Approve or reject in bulk by CSV

Export the pending queue, fill the action column and upload (UI ≤ 30 rows). The server validates every row first — any bad row rejects the file — then applies each with the normal seat, start-date and clash rules.

POST workflow/blendedprogram/getUserApprovalDataInCsv · bulkApprovalDataFromCsv/:contentId
MDO Admin
UC-11 · Act as MDO admin

The workflow endpoints for MDO exist (update/mdo, searchV2/mdo, admin/enrol, remove/mdo), but no screen in the attached UI repos calls them. Verification boundary: the MDO-side UI, if any, is outside the attached repos.

POST workflow/blendedprogram/update/mdo · admin/enrol
Coordinator / MDO Admin
UC-12 · Nominate learners

Writes the request straight to APPROVED: ≤ 200 users per call, PC overrides an earlier MDO or self request, MDO overrides only self, hard seat cap, clash check; per-user results come back. Hidden from instructors.

POST workflow/blendedprogram/nominate
Coordinator / MDO Admin
UC-13 · Remove an enrolled learner

Before the batch starts. The request becomes REMOVED and an un-enrol goes to the course service.

POST workflow/blendedprogram/remove/approved/user
Program Coordinator
UC-14 · Mark attendance

Enabled from the session’s start date until batch end + 7 days (a Creation Portal rule). Present writes 2 / 100%, absent 0 / 0%; the learner is emailed.

POST blendedprogram/v1/update/progress
Coordinator / Instructor
UC-15 · Evaluate assignments

Marks 1–99 999 (not above the maximum) and feedback ≤ 500 chars. Deleting an assignment in the UI removes it from the list only.

POST assignment/v1/feedback · v1/notifyAssignment/evaluate
Program Coordinator
UC-16 · Generate reports

Enrollment (v1) and Consumption (v2) reports, asynchronous via Kafka; the v2 report has no session or attendance columns — those exist only in the nightly Spark CSV.

POST bp/v1/generate/report · bp/v2/generate/report · bp/v2/bpreport/list

Authoring & batch management (Creation Portal)

Author / Reviewer / Publisher
UC-17 · Author and publish the program

Create with the Blended Program radio; hierarchy holds Modules, Resources, Session Templates, optional Pre / Final assessments (Course children are stripped on save); program fields include duration, approval type, self-enrolment, batch settings and ≤ 5 coordinators; review, publish (children first). Retire only via the generic retire call.

POST action/content/v3/create · PATCH …/hierarchy/update · DELETE v1/content/retire
Program Coordinator
UC-18 · Staff the program

Add coordinators and National / State lead trainers (≤ 5 each) from the types in the program’s batch settings; removal is blocked while they own or co-train an active batch.

POST program/coordinator/list/:doId · PUT program/coordinator/:doId
Coordinator / Trainer
UC-19 · Create a batch with sessions

Size 1–200 (stored as a string), dates, enrolment end, venue + latlong (needed for QR attendance), instructors, cadre list, profile-field mode; one session card per Session Template. Side effects: profile survey form, co-trainers, default certificate template.

POST authApi/batch/create · forms/v2/createForm · PATCH course/batch/cert/v1/template/add
Coordinator / Trainer
UC-20 · Maintain a batch

Name and size locked on edit. Delete only before the start date — and it un-enrols every learner and emails them. Archived batches accept only new instructors.

PATCH authApi/batch/update · POST learner/course/v1/batch/delete
Program Coordinator
UC-21 · Print the QR codes

Two different PDFs: the self-enrolment QR (needs selfEnrollment = Yes) and one attendance QR per offline session.

GET batch/v1/enrollment/qrcode/… · batchsesion/qrcode/:courseId/:batchId

Edge cases worth documenting

SituationBehaviour
Learner in another Blended Program with overlapping datesThe web client check only sees the program being viewed, so it never fires. The server rejects at enrol, and runs the same check on every approve / withdraw, where a hit silently becomes a REJECT. An existing batch that fully encloses the new one is not detected.
Batch fullRequests are allowed up to size + 20%; approval and nomination are hard-capped at size. currentBatchSize of 0, missing or a JSON number reads as full.
Batch already startedApprovals are refused ("This batch is already in progress") except REJECT/WITHDRAW; removal is refused too.
Withdrawal after approvalNot offered by web or mobile. A withdrawn or rejected row never un-enrols.
Reject without a reasonBlocked in the Creation Portal; the server does not require one.
AttendanceMobile adds a live-session window and a 1 km fence; a batch with no latlong cannot mark attendance on mobile.
