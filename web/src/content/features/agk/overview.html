What it is

A user opens Amrit Gyaan Kosh (code name “Gyaan Karmayogi”) from a hub tile (mobile) or a direct route (web), and lands on a page split into “Case Studies” (content authored by the Capacity Building Commission) and “Other Resources”, filterable by sector, sub-sector, resource category, SDG, state/UT and year. Opening a resource routes into a mime-type-dispatching player — PDF, audio, YouTube or video — that wraps a shared platform viewer library. The web portal and mobile app each built this independently, in parallel.

Honest gap: there is no “Amrit Gyaan Kosh service” anywhere in the eight repos traced for this feature. Both clients call a generic content-search endpoint that is not implemented in any repo analyzed, and the Case-Studies/Other-Resources split is just a content filter (an org-id match) configured twice, independently, once per platform — with no shared source of truth between them.
No dedicated backend

The entire server-side footprint is a handful of unconstrained schema fields in knowledge-platform and a sector-taxonomy CRUD API in sunbird-cb-ext.

Two clients, no shared contract

Web and mobile each declare their own field-name constants and request-building logic for the same metadata — they agree today by convention, not by a shared library.

Authoring is generic

Resource content is created through the platform's ordinary content-creation flow; no dedicated AGK authoring screen exists anywhere.

How a Karmayogi experiences it

1 · FIND

Hub tile (mobile) or direct route/deep link (web, incl. from global search and the AI assistant)

2 · LAND

Facet chips, a content-strip carousel, Case Studies vs Other Resources tabs

3 · FILTER

Sector, sub-sector, resource category, SDG, state/UT, year

4 · VIEW ALL

Paginated / infinite-scroll grid of matching content

5 · OPEN

Mime-type player: PDF, audio, YouTube or video
